# 05　常见坑（报错先看这里）

## 环境与编码

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 命令报错或打开应用商店 | Windows 上的 Store 占位程序 | 用 `py -3` 或虚拟环境里的完整路径 |
| 中文输出乱码 / `UnicodeEncodeError` | 控制台代码页不是 UTF-8 | 设 `PYTHONIOENCODING=utf-8`；写文件一律 `encoding="utf-8"` |
| 用管道把中文脚本喂给 python 变成 `?????` | 管道按本地代码页解码 | **先写成 `.py` 文件再执行**，不要 `echo ... \| python -` |
| PowerShell 重定向后读回乱码 | 默认 UTF-16 / GBK | 中文文本校对用 Python 直接读写 UTF-8 |
| `PermissionError` / 写入半截 | docx 被 Word 或预览器占用 | 关闭打开的文件再重建 |

## 数值与格式

| 现象 | 原因 | 处理 |
|---|---|---|
| 百分比多乘了 100（0.01 → 1.000%） | 变量本身已是百分数，又用了 `%` 格式符 | 统一 `f"{x:.3f}%"`，在常量名里写明单位 |
| Excel 打开显示 `#NAME?` | 格子里写了 `= 说明文字`，被当公式 | 说明文字不要以 `=` 开头 |
| 峰面积显示成 `150278.0` | 数字格式用了 `0.0` | 大整数用整数格式 |
| 长文本被截断 | 合并单元格不会自动撑开 | `wrap_text=True` + **按文本宽度估算行高**并显式设置 |
| 表头折行断在词中间 | 列宽不足 | 改两行式表头并加宽列 |
| 校验取表行取错 | 同一符号在某列出现两次（限量值与换算值） | 以"项目"列作键，不要用符号列 |
| 换算差 10⁶ 倍 | μg 与 g 混用 | 常量名带单位，换算只做一次 |

## 内容（最容易返工）

| 坑 | 处理 |
|---|---|
| 为了"好看"把不合格改成合格 | **禁止**。如实报 + 讨论章给复核路径 |
| 单份测定补编 s / RSD | **禁止**。`n < 2` 返回 `None`，正文显示「—」 |
| 课件没有的实测值自己填 | **禁止**。留「（待填）」或问用户 |
| 仪器/试剂做成大表 | 改文字列举（表格留给一手数据） |
| 删章后编号跳号 | 一级标题必须连续；删表后表号**重排** |
| 手写记录与课件符号冲突 | 按课件口径，加**批注**说明 |
| 谱图把所有峰都录进去 | 只取目标峰那一行（除非本次就是杂质分析） |
| 转录稿与原始图不一致 | **以原图为准** |
| 拿错同名文件（多份 `模板.docx`、语义各异的 `verify.py`） | 一律用**绝对路径** |
| 报告的数值与工作簿对不上 | 一定是有人手改了其中一个——回到 `_data.py` 重跑 |

## 校验

- 判断 docx 默认字号必须**逐层取** `docDefaults/rPrDefault/rPr/sz`。
  用 `ET.tostring` 转成字符串再找 `w:sz` 会失败——命名空间前缀会被改写成 `ns0:`。
- 排版工具常报两类"启发式误报"：
  「段落缺少首行缩进」（命中的是标题和居中的公式行，本就不该缩进）、
  「中英标点混用」（命中的是「1、」这类中文编号）。**确认后不必改**。
- 校验只做结构检查是不够的。**必须有一节做数值复算**，
  否则"文件完好但数字错了"这类问题永远发现不了。

## 流程

- **不要跳过 `_data.py` 的自检打印**。它是唯一能在排版前发现计算错误的地方。
- **不要在构建脚本里硬编码结果字符串**（如 `b.p("含量为 87.30%")`）。
  换数据时它会静默变成错数字，而校验如果只查结构就查不出来。
- **换数只改输入区**。改了派生量等于把可复现性丢掉。
- **升版前先存快照**。覆盖掉之后就没有回滚点了。
