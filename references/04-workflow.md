## 3. `_data.py` 的写法

只有两类内容：

```python
# ① 输入区：口径常量 + 原始记录（人改这里）
METHOD = "高效液相色谱法（外标法）"
V_FLASK = 50.0            # mL
W_SAMPLE_G = 0.2742       # g
C_STD = 0.5058            # mg/mL
CONTENT_LOWER, CONTENT_UPPER = 93.0, 107.0
MEASURED = [(1, 4.671, 512340.0), ...]   # 原始读数，照录

# ② 派生量：全部由上面算出来（人不要改这里）
def content(): ...
def summary(): ...
```

`if __name__ == "__main__":` 里打印**全部中间量**，这是它作为"自检器"的价值：

```
取样 20 片；定容 50 mL；称样 0.2742 g；相当量 25 mg
A对 = 515766.67   A样 = 489458.33   比值 = 0.9490
C样 = 0.4800 mg/mL → 测得量 24.00 mg
含量 = 96.00%   限度 93.0%~107.0% → 符合规定
```

格式一律用常量引用（`f"{D.content()['mean']:.2f}"`），**不要在构建脚本里手写结果**。

## 4. 构建脚本的写法

### Word

```python
import _data as D
from docx_builder import DocxBuilder

b = DocxBuilder()                      # 紧凑型；DocxBuilder("loose") 为宽松型
b.cover("××的含量测定", "实验报告")
b.h1("一、实验目的")
b.p("1. 掌握……")
b.h1("五、数据记录、计算与判定")
b.h2("（一）原始数据记录")
b.caption("表 1　吸光度记录")
b.table(
    ["溶液", "A(λ₂)", "A(λ₁)", "ΔA"],
    [["空白", "0.009", "0.009", "0.000"],
     ["对照品", "0.648", "0.002", "0.646"]],
    widths=[4, 2, 2, 2],
)
b.note("① 划改处取改后值。")          # 表注
b.save("03_output/报告_v1.docx")
```

`docx_builder.py` 提供：`cover / h1 / h2 / h3 / p / pc / caption / table / note / picture / page_break / save`。

> 口径说明（为什么取这个波长、为什么剔除某个点）建议写成文末一段独立的「附注」正文，
> 而不是依赖 Word 批注——批注 API 在各文档库支持不一，正文段落永远可读、可校验。

### Excel

```python
from xlsx_builder import XlsxBuilder
import _data as D

C = D.content()

x = XlsxBuilder(["使用说明", "数据输入", "计算", "公式与依据"])
x.title("使用说明", "A1", "××数据处理", span="A1:H1")
x.section("数据输入", "A3", "一、原始读数", span="A3:E3")
x.head_row("数据输入", 4, ["序号", "保留时间/min", "峰面积", "备注"])
x.row("数据输入", 5, [1, 4.671, 512340, ""], fill_input=True, num_fmts={2: "0", 3: "0"})
x.row("计算", 6, ["含量/%", f"{C['mean']:.2f}", "", f"C样×V÷相当量×100"])
x.row("计算", 7, ["含量（公式复算）", "=B5*50/25*100", "%", "引用数据输入"])
x.widths("数据输入", {"A": 10, "B": 16, "C": 14, "D": 40})
x.save("03_output/数据处理.xlsx")
```

> **`save()` 内部会自动调 `autofit_rows()`**，按文本长度估算行高——
> 这是长句不被截断的关键，不要绕过 `save()` 自己调 `wb.save()`。

> **公式与说明文字的区别**：以 `=` 开头、后面是函数名/单元格引用（如 `=AVERAGE(数据输入!C4:C8)`）
> 会被当作公式；以 `=` 开头但后面接中文（如 `= 相当量25mg / 50mL`）会被 `XlsxBuilder` 拦下报错，
> 避免打开时显示 `#NAME?`。确实想写这种说明时，去掉前导 `=` 即可。

## 5. 只读校验（`verify.py`）

十节结构，每节若干 `check()`，末尾 `汇总：PASS N / FAIL 0`：

| 节 | 检查项 |
|---|---|
| ① 结构 | docx 内部 XML 全部可解析；正文段落数 > 0 |
| ② 页面 | 纸型 A4、页边距等于设计值 |
| ③ 默认版式 | 默认字号、行距符合设计（逐层取 `docDefaults/rPrDefault/rPr/sz`） |
| ④ 标题序列 | 一级标题个数与**编号连续无跳号**，并与预期列表全等比对 |
| ⑤ 表格 | 表数符合设计；三线表边框（顶/底粗、表头下细、无竖线）；表题编号连续 |
| ⑥ 数值复算 ★ | **正文每个数值与 `_data.py` 独立复算比对** |
| ⑦ 判定一致性 | 判定文字 ↔ 限度区间 ↔ `pass` 布尔量 |
| ⑧ 内容纪律 | 无被剔除数据的残留；`（待填）` 状态与开关一致；`n<2` 处不出现 s/RSD |
| ⑨ 工作簿 | 表数、公式数、错误格数为 0；读回缓存值与 `_data.py` 对照 |
| ⑩ 收尾 | 两份文件都能被对应库正常打开（`Document()` / `load_workbook()`） |

**第 ⑥ 节是校验的价值所在。** 结构检查只能发现"文件坏了"，
数值复算才能发现"数字算错了"。新增一个数值，就新增一条复算检查。

## 6. 版本流程（六步）

1. 改 `_data.py`（或构建脚本）
2. 当前 docx **另存快照**到 `04_history/vN_*.docx`
3. 构建脚本与 `verify.py` 里的输出文件名**递增**
4. 重跑：`_data.py` → `build_xlsx.py` → `build_docx.py`
5. `verify.py --save` 必须全绿
6. `04_history/MANIFEST.md` 追加一行（版本 / 差异 / 规模 / 校验结果）

> ⚠️ 重建前确认文件**没有被 Word / 预览器打开**——Windows 上会锁文件，
> 报 `PermissionError` 或写入半截文件。
> 若用编辑器插件改过 docx，**改动要同步回构建脚本再重建**，
> 否则下次重建会把它覆盖掉。

## 7. README 模板

```markdown
# <实验名> —— <课程>

> 一句话：做什么 + 用什么方法 + 结果类型。

## 实验口径（来自课件/讲义，勿擅改）
★ 逐条列出口径 + 本组数据 + 计算式 + 限度

## 关键数值
结果表 + 判定（与 `_data.py` 逐值一致）

## 复现
python _data.py && python build_xlsx.py && python build_docx.py && python verify.py --save

## 目录与脚本
| 目录/脚本 | 用途 |

## 版式
用的是紧凑型还是宽松型，参数摘要

## 已知问题 / 待确认
★ 数据异常、只有单份、待填项，都写在这一节
```

**「已知问题」这一节不要省**——它决定了三个月后的你能不能看懂当时的判断。

## 8. 可选：其它渲染后端

默认后端是 `python-docx` + `openpyxl`，够用且零外部依赖（除 pip 包）。

如果环境里有更强的文档 CLI（批处理式、支持声明式指令），可以把
"生成指令 JSON → 交给 CLI 写盘"作为替代后端。此时仍然保持两条：

1. 构建脚本**不直接改已有文档**，只生成指令；
2. 指令文件保留在仓库里，作为版式的可 diff 记录。

切换后端只影响 `build_*.py` 的最后一步，`_data.py` 与 `verify.py` 不受影响——
这正是"生成与写入分离"的好处。
